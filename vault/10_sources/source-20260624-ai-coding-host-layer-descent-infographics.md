# AI Coding 宿主层级下沉图组

## Why Save

这组图的价值不在于单个市场数字，而在于它提出了一个可以复用的产品判断框架：AI Coding 的竞争焦点可能从“模型能力与编辑器功能”转向“宿主层级、上下文驻留、自动反馈循环和入口控制”。

## Extracted Core Thesis

每一代 AI Coding 产品都不只是上一代工具的优化版，而是在抢占更底层、更常驻的宿主入口：

- Gen 1：编辑器宿主。代表形态是 Cursor 一类的 IDE/Editor 集成。
- Gen 2：终端宿主。代表形态是 Claude Code 一类的 terminal-first coding agent。
- Gen 3：个人 OS + IM 宿主。附件用 OpenClaw 表达这个方向：agent 常驻在本地权限、记忆、任务与沟通入口之间。

由此推导出的关键判断是：下一代产品的优势可能不来自“更会补代码”，而来自“能否长期驻留在一个目标函数上，自行观察结果、修改策略、继续执行”。

## Evidence Claimed By The Attachments

附件把四类信号串成同一条逻辑链：

- 收入与增长曲线：Claude Code 的收入曲线被描述为已反超 Cursor，OpenClaw 被描述为早期增长陡峭。
- 行业路线投票：Anthropic、NVIDIA、OpenAI、DeepSeek 等被放入矩阵，用来观察它们是否在向 OpenClaw 所代表的下一代宿主形态靠拢。
- Autoresearch 案例：Karpathy 的 Nanochat 训练优化、Shopify 的渲染性能优化，被作为 agent 在目标函数上连续自我改进的早期信号。
- 宿主入口扩张：潜在用户池从会装 VS Code 的开发者，到会开终端的工程师，再到拥有手机 IM 的用户。

这些事实性主张需要外部来源复核；本条 source 只确认附件表达了这些主张，不把具体收入、star、下载量或厂商路线当作已验证事实。

## Useful Lens

判断一个 AI coding / agent 产品时，可以问五个问题：

1. 它宿主在哪一层：编辑器、终端、浏览器、OS、IM、企业硬件还是云平台。
2. 它是否拥有持续上下文：文件、shell、权限、记忆、用户意图、运行指标和历史尝试。
3. 它是否能闭环：生成动作、观察指标、判断改进、再次行动。
4. 它能否跨任务驻留：一次 chat、一次 session、一个项目，还是长期个人/团队代理。
5. 它的入口是否扩大潜在用户池，并提高切换成本。
